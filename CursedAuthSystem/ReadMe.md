# Я с ним боролся, но он оказался сильнее

## Предположения
1. LogTo - хороший провайдер, удобный
2. OAuth2-Proxy - натуральное проклятие: как в анекдоте:
    - В магазин ходил?
    - Да
    - Денег дала?
    - Да
    - Хлеб где?
    - Какой хлеб?
3. OAuth2Proxy reject'ил все мои авторизации, хотя вход/регистрация были.
Это видно по логам LogTo, видно по пустым сессиям/куки (я честно не понимаю, почему они пустые).

## Как заполнялось LogTo Admin

1. http://localhost:3002
2. Аккаунт-админ произвольный, какой он значения не имеет.
3. В Applications нужно создать Traditional Web App
4. Для этого тык по `Third-party apps`
5. Тык по `Traditional web`
6. Имя приложения произвольное
7. В redirect URI значение из конфиг-файла oauth2-proxy (Redirect URI: `http://localhost:4180/oauth2/callback`)
8. `App ID` копируется в config.toml под видом client
9. `App secret` копируется в config.toml под видом client
10. Тык по вкладке Permissions: все из `scope` в config.toml
11. Потом создаём вход-регистрацию: `Sign-in&account`: там, после подтверждения, нужно перейти на вкладку `Sign-up and sign-in`, в самом низу -- редирект ссылка для открытия входа. Если LogTo не узнал сессию -- туда перенаправит. Указывал `Unknown session redirect URL: http://localhost:4180/`
12. После этого можно запустить всё, перейти на http://localhost:3002, зарегистрироваться
13. После регистрации обратно http://localhost:3002 открываем, там `User management`
14. Нажимаем по пользователю, даём пользователю почту (иначе OAuth2Proxy тоже будет скандалить, мол опираться не что при создании токенов)
15. Всё. Пробуем войти в инкогнито. ДОЛЖНО ПОЛУЧИТСЯ. ПРОБЛЕМА БЫЛА В НЕВЕРНОЙ КОНФИГУРАЦИИ ФАЙЛОВ.
